# Preliminary Model Assumptions

| Topic | Minimum Viable Model | Possibilities for Future Development | Rationale |
|---|---|---|---|
| **Nodes** | Nodes represent people or resources. | Expand node representations to include any entity that can serve as a point of connection. | Limiting node types simplifies visualization and initial implementation. |
| **Edges** | Edges represent different types of relationships between people. | Expand edge types to represent additional relationships. | Edges establish the connections through which resources can be transferred. |
| **Graph Structure** | Implement a directed, multilayer graph in which each layer represents a distinct relationship or resource type. Representations of the same person may connect across different layers. Maintain a separate knowledge graph. | Develop the ability to convert or derive the multilayer graph from the knowledge graph. | The knowledge graph will facilitate querying and may provide additional flexibility for refining the model. |
| **Layers** | Each layer represents a distinct resource relationship or relationship type between people. | Maintain the same structure while allowing additional layers. | Layers provide a way to distinguish between different types of relationships and resource interactions. |
| **Weights** | Edge weights represent the proportion of resources transferred to different nodes. | Implement an intermediate layer using an adjacency matrix in which weights represent the probabilities of connections existing between nodes. Use this matrix to sample randomly generated graphs. | Introducing probabilistic uncertainty will allow the model to account for uncertainty in network connections. |
| **Self-Loops** | Self-loops are excluded. | Maintain the same assumption unless future requirements justify reconsideration. | Self-loops introduce additional complexity when working with directed acyclic graphs (DAGs). |
| **Directed Graphs** | All graphs will be directed. | Maintain directed graphs across future implementations. | Directed edges are necessary to represent the directionality of relationships and resource transfers within the simulation. |
| **Isolated Nodes** | Isolated nodes are permitted. | Maintain support for isolated nodes. | Nodes without connections in one layer may still be connected to other nodes in different layers. Removing them could introduce bias or result in information loss. |
| **Database** | Neo4j will serve as the primary graph database. | Reevaluate the database selection if limitations or more suitable alternatives are identified. | Neo4j provides a reasonable starting point for graph storage and querying. |
| **Division of Responsibility** | Use separate Python libraries for simulation and adjacency matrix generation, with Neo4j handling database operations. | Maintain the same general architecture. | Separating functionality into distinct components allows for improved modularity and scalability. |
| **Negative Balances** | The treatment of negative balances will depend on the dataset selected. | Explore the possibility of modeling debt. For resource-based layers, balances could also be constrained to a minimum of zero to represent resource depletion, where appropriate. | Modeling debt requires supporting data, while resource constraints should reflect the behavior of the resource being modeled. |
| **External Flows** | External resource flows are excluded from the initial model. | Consider incorporating external resource flows in future implementations. | External flows are not necessary for the minimum viable model but may eventually capture additional behaviors relevant to the network. |
| **Iterations** | The adjacency matrix and network structure remain constant across iterations. | Allow edge connections and weights to change between iterations. | Dynamic connections and weights would allow the model to capture changes in network structure over time. This functionality could be integrated alongside probabilistic edge generation in future implementations. |
| **Output** | Report final resource totals, eigenvalues and eigenvectors, and changes from the initial input. | Include changes in edges and the final graph structure. | Outputs should provide the results and data necessary for interpreting the model. Future dynamic implementations should also capture how the graph changes over time. |
| **Visualization** | Use Neo4j to visualize the basic graph structure. | Investigate additional visualization methods and tools. | Neo4j provides sufficient visualization capabilities for the initial static graph. As the network becomes dynamic, additional tools may be needed to display structural changes over time. |
| **Initial Resource Distribution** | Assign starting wealth using a normal distribution informed by where individuals live. | Experiment with alternative methods for representing the initial distribution of wealth. | A normal distribution provides an initial approach to modeling resource distribution, with the possibility of exploring more suitable methods as the model develops. |
